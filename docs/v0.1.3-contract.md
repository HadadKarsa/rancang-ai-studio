# v0.1.3 — contract (becik, 2026-11-22)

Locked shapes for the round. No new backend endpoint is introduced: every
screen below reads what v0.1.2 already serves. This file exists so the UI and
the backend agree on what is read and how it is shaped before the UI depends
on it.

## 1. Shell — one rail, every app page

- `src/components/AppShell.tsx` renders the rail plus `<main className="content">`.
  It is the only place the shell is defined.
- Mounted by `(studio)/layout.tsx`, `library/layout.tsx`, `projects/layout.tsx`
  and `docs/layout.tsx`. Public routes (`/`, `/login`, `/register`, `/share/**`)
  mount nothing: they stay clean.
- Nav: Studio `/studio`, Library `/library`, Models `/models`, Dokumentasi `/docs`.
- Collapse state: `localStorage["rancang.rail.collapsed"]` = `"1"` | `"0"`,
  read on mount, written on toggle. The toggle is a `<button aria-expanded>`
  with `aria-controls="rail-nav"`; collapsed links keep their accessible name
  through `aria-label` and a `title`.

## 2. Project page — `GET /api/v1/projects/:projectId`

Existing response, unchanged:

```
{ project: {id,name,slug,status,accentColor,description,updatedAt},
  documents: [{id,type,title,status,orderIndex,lastGeneratedAt,currentVersionId}],
  tags: string[], counts: Record<string, number> }
```

- `documents[].status` is one of `pending|generating|ready|failed|stale`.
  The project page treats `ready` as "has text to show" and the rest as
  "not written yet".
- Primary content when at least one document is `ready`: the document list.
  Secondary control: "Lihat wawancara" → `/projects/:id/interview`.
- No ready document: the page leads to the interview instead.

## 3. Preview pane — `GET /api/v1/projects/:projectId/documents/:type?content=1`

Existing response, unchanged:

```
{ document: {id,type,title,status,...}, content: string | null, versions: [...] }
```

- The project page fetches one document's markdown on selection, keeps it in
  memory (a `Map<type, string>`), and renders it with `react-markdown` +
  `remark-gfm`. No new endpoint, no raw HTML injection.
- Default selection: the first document whose `status === 'ready'`.
- `wireframe` documents are HTML, not markdown: the preview links to
  `/projects/:id/documents/wireframe` instead of rendering them.

## 4. Library — `GET /api/v1/library`

Existing response, unchanged. The page regroups it client-side:

```
items: [{id,kind,title,projectId,projectName,documentId,documentType,createdAt,bytes}]
```

- Group key: `projectId`. A group becomes one card: name, artifact count,
  newest `createdAt`, and a ZIP button.
- ZIP: `GET /api/v1/projects/:projectId/export?format=zip` (existing, proven).
  The button is an `<a download>` to that URL — no client-side zip builder.
- `projectId === null` items go to a separate "Simpanan lepas" section.
- Nothing in the library navigates to a detail page. Delete stays, at project
  card level, labelled with what it removes.

## 5. Documentation — `/docs`

Static page, no API. Content must match the code: model setup
(`/models`), project creation (`POST /api/v1/projects`), interview
(`/projects/:id/interview`), writing (`/projects/:id/write`), documents
(`/projects/:id/documents/:type`), export (`?format=md|zip|json`), library,
wireframe editor, share link (`POST /api/v1/projects/:id/share`).
Not built, therefore not documented as available: PDF export, cloud auth,
team collaboration.

## Rules

- Backend owns `src/lib/**` and `src/app/api/**`; UI owns pages, components
  and `globals.css`. This round the UI needs no backend change.
- `npx tsc --noEmit` before every commit. Indonesian copy, no emoji.
